# OpenVINO 装甲板检测模块交接文档

## 1. 模块概览 (Overview)

本模块 (`ModelDetector`) 是 RoboMaster 机器人视觉自瞄系统的核心组件之一。它基于深度学习（YOLO 姿态估计变体）实现对敌方装甲板的高帧率检测。

为适应算力平台（如 Intel NUC 或其他仅带 CPU/核显的迷你主机），本模块采用 **OpenVINO 2.0 C++ API** 进行推理部署。

> **注意**: 当前实现为独立的 `ModelDetector` 类，**不继承** `DetectorBase` 基类（已移除继承关系），直接与 `armor_detector_node.cpp` 对接。

---

## 2. 模型规格 (Model Specifications)

本模块加载的 ONNX 模型需严格满足以下输入输出规范：

### 输入 (Input)

* **节点形状 (Shape)**: `[1, 3, H, W]` (通常 H=W=640)
* **网络真实接收格式**: `FP32`, **RGB** 通道顺序, 像素值归一化至 `[0.0, 1.0]`。
* **工程实现说明**: 在 C++ 代码中，只需直接传入相机获取的原始 `cv::Mat` (`CV_8UC3`, **BGR** 顺序)。通道翻转 (BGR->RGB)、数据类型转换 (u8->f32) 和归一化操作均已通过 OpenVINO 的 **`PrePostProcessor (PPP)`** API 融入底层计算图，由硬件自动加速处理，**切勿在 C++ 中手动除以 255**。

### 输出 (Output)

* **节点形状 (Shape)**: `[1, 22, N]` 或 `[1, N, 22]` (N 为预测框/候选装甲板的数量)。
* **维度解析 (22 维)**:

| 索引 (Index) | 长度 | 物理含义 | 详细说明 |
| --- | --- | --- | --- |
| `0 - 7` | 8 | 4个关键点坐标 | 顺序：**左上 → 右上 → 左下 → 右下** (counterclockwise from top-left) |
| `8` | 1 | 目标置信度 (Objectness) | 预测框内存在有效装甲板的概率（需计算 `sigmoid`） |
| `9 - 12` | 4 | 颜色分类 (Color) | 详见下方映射表 |
| `13 - 21` | 9 | 数字/类别分类 (Class) | 详见下方映射表 |

## 4. 数据流与处理管线 (Pipeline)

### 1️ 预处理：Letterbox (等比例缩放与填充)

为了防止装甲板在输入网络时因强制 `resize` 导致长宽比失真（影响姿态和大小装甲判断），模块采用了 Letterbox 预处理：

1. 计算缩放因子：`scale = min(640/原图宽, 640/原图高)`
2. 将原图等比例缩放。
3. 在图像边缘填充灰色像素 `(114, 114, 114)` 至 640x640。
4. **保留 `scale`、`pad_x`、`pad_y**`，这是后处理坐标反算的唯一凭证。

### 2️ 后处理：解析与还原

1. **基础过滤**: 取 `sigmoid(output[8])` 得到 `objectness`，低于 `confidence_threshold` 直接丢弃。
2. **多类别评分**:
   * 取颜色类别最大值索引。
   * 取数字类别最大值索引，计算 `class_prob = sigmoid(max_num_prob)`。
   * **最终置信度**: `final_score = objectness * class_prob`。


3. **坐标反算 (核心易错点)**:
   网络输出的坐标是基于 640x640 且带有黑边的，映射回原图必须**先减去黑边平移量，再除以缩放比例**：
   ```cpp
   x_orig = (x_pred - pad_x) / scale;
   y_orig = (y_pred - pad_y) / scale;
   ```

4. **NMS 去重**: 使用 `cv::dnn::NMSBoxes` 消除同一装甲板上的重叠预测框。
5. **装甲板重构**:
   * 利用 4 个角点重构左右灯条 (`Light`) 的 `top` 和 `bottom`。
   * 计算长宽比，大于 `3.2` 判定为 `LARGE` (大装甲)，否则为 `SMALL` (小装甲)。

## 5. 代码结构

### 类定义

```cpp
class ModelDetector {
public:
  ModelDetector(const std::string &model_path,
                float confidence_threshold,
                float nms_threshold,
                EnemyColor detect_color);

  void drawResults(cv::Mat &img) const;

  // Parameters
  EnemyColor detect_color;
  float confidence_threshold;
  float nms_threshold;

  cv::Mat letterbox(const cv::Mat &src, float &scale, float &pad_x, float &pad_y);
  std::vector<Armor> postprocess(const float *output_data,
                                 int num_candidates,
                                 float scale,
                                 float pad_x,
                                 float pad_y);

  // OpenVINO 推理成员
  ov::Core core_;
  ov::CompiledModel compiled_model_;
  ov::InferRequest infer_request_;

  // 预分配的转置 Buffer

};
```

## 6. 性能优化

* **内存复用**: 检测到模型输出为 `[1, 22, N]` 时需要进行维度转置 (Transpose)。为避免视频流处理时每帧发生堆内存分配（导致 CPU 占用飙升和降帧），已在类中预分配 `std::vector<float> transposed_buffer_`，并在 `detect` 循环中复用。

## 7. 避坑指南 (Troubleshooting)

1. **画面中检测框严重偏离装甲板（漂移）**
   * **原因**: Letterbox 坐标反算错误。
   * **排查**: 检查 `postprocess` 函数中是否正确接收并使用了 `detect` 函数计算出的 `pad_x`、`pad_y` 和 `scale`。不可直接乘以 `原图宽/640`。


2. **所有置信度极低或检测不到任何物体**
   * **原因**: 颜色通道错乱或重复归一化。
   * **排查**: 确认输入 `detect()` 的确实是 `BGR` 格式。确认 C++ 代码中没有手动除以 255（`PrePostProcessor` 已经做过了，再除一次会导致输入全黑）。


3. **终端报错：Vector index out of bounds 或模型崩溃**
   * **原因**: 模型实际导出的维度与代码中定义的 `NUM_NUMBERS` 不匹配。
   * **排查**: 用 Netron ([https://netron.app/](https://netron.app/)) 检查模型 `.xml` 或 `.onnx` 的最终输出节点，确认维度是 22（当前实现）还是 23。相应修改头文件中的 `NUM_NUMBERS`。

4. **编译报错：找不到 detector_interface.hpp**
   * **原因**: 之前版本尝试继承 `DetectorBase` 基类，但该文件不存在。
   * **排查**: 确认 `model_detector.hpp` 中没有 `#include "armor_detector/detector_interface.hpp"` 且没有 `: public DetectorBase` 继承。当前实现为独立类。
